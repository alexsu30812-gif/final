# DeepMIR 期末專題｜指定副歌條件下的完整歌曲生成

這是 2026 年 11 月 24 日的研究構想與交接快照。換電腦後先讀本頁，再看[四週團隊計畫](DeepMIR_Final_Project_四週團隊計畫.md)的分工與交付日期。本快照收錄提案、設計與待驗證假說，目前還沒有生成程式、模型權重、歌曲素材或實驗結果。

## 題目與假說

給定歌手 **A** 的創作條件，以及既有歌曲 **B** 的指定副歌，產生一首完整新歌。A 的條件包括音域、配器、律動與樂句習慣。B 提供須保留的副歌歌詞、旋律與時間邊界。主要研究問題是 **系統依據副歌安排曲式及出現位置，能否比固定曲式接得更自然？**

| 待驗證的假說 | 怎麼驗證 |
| --- | --- |
| 自動規劃能改善進出副歌的自然度與全曲連貫性 | 用同一組 A、B 比較固定曲式與自動規劃，做接點與全曲的配對盲聽。兩組共用生成器、素材、總長、副歌次數、填詞與接點處理規則、種子和重試預算。 |
| 弱起、樂句長度和首尾和弦能幫助規劃器選到更合適的曲式 | 若進度允許，對同一套規劃器拿掉副歌特徵，保留相同候選與生成預算。若有預設和弦骨架，可先估計候選和聲相容度，再用成品確認效果。 |
| 先有音樂再填詞，可以保留既有旋律與伴奏 | 原提案的延伸實驗。從導唱或 MIDI 得到每句音符、起訖、休止與延音，依音節填詞後獨立重唱。比較填詞前後的音高、時值、可懂度與副歌完整性。 |
| 接近或相隔較遠的年代配對，可能有不同的接點難度 | 若進度允許，在曲風等條件相近時比較年代差異。若要檢驗年代篩選本身，則在同一檢索器中比較保留與移除年代條件。 |

## 12 月 22 日的建議版本

- **正式實驗**先人工選 A、B 配對，限定英文，涵蓋三種曲風。檢索另外做簡單 demo，先依曲庫的曲風與年代資料篩選，再用 MERT 特徵排序。定案前，曲風種類和年代差距以四週計畫的候選為準。
- **副歌**使用核對過的錄音，依團隊允許的幅度做移調與變速，保護弱起和尾音。四週計畫提出最多 2 個半音及速度變動 8% 作為討論選項，尚待確認。
- **填詞順序**暫以四週計畫的建議開發：先請 LLM 按每句音節預算寫新段歌詞，再由 ACE-Step 生成。原始[目標](目標)與[研究提案](Chorus_Conditioned_Song_Generation_Proposal_zhTW.md)採先生成音訊再填詞，並允許重唱副歌。四週計畫把這兩項列為延伸，生成順序仍需團隊確認。
- **生成**先測 ACE-Step 1.5 2B Turbo 的 Repaint。核心版本使用現成權重；Seam LoRA、SoulX-Singer 重唱與依既有音訊填詞列為延伸。YuE2、MuLaCover 是比較與文獻候選。
- **評估**分開報告副歌保留、接點自然度、全曲結構與成本。三組生成方法按計畫是直接條件生成、固定曲式和自動規劃，另有人工直貼的接點參考。若直接生成組的副歌條件方式不同，主假說以固定曲式對自動規劃回答。

## 建議實作流程

1. **資料與分析**：人工選 B，All-In-One 標拍點、重拍與段落；需要抽主唱時用 Demucs。SheetSage 提供旋律與和弦草稿，Whisper 提供歌詞草稿，副歌邊界和詞曲回聽確認。A profile 另外整理創作條件，供規劃、填詞和生成共用。
2. **曲式規劃**：固定版和自動版都輸出 `plan.json`。自動版列舉合理曲式，再依副歌弱起、樂句長度、可用鋪陳空間及候選和弦骨架排序。兩組共用調性與 BPM 時，把它們放在對齊條件裡。
3. **歌詞**：依段落與音節預算產生新段落的英文詞，程式核對音節數。指定副歌使用已核對的原詞。團隊仍要選擇本地 LLM 或已有額度的 API。
4. **組裝與生成**：對齊 B 的速度與調性，把副歌放進完整長度的來源時間軸。將小節換算為秒，交給 ACE-Step 做指定區間的 Repaint，保留對齊後的副歌軌供比對及必要時貼回。若填接不自然，先從同拍速草稿只修接點的版本驗證。Repaint 的輸出長度跟隨來源音訊。
5. **驗收**：比對保護區、確認詞曲、檢查新段音域。副歌前後盲聽評接點，完整歌曲盲聽評結構。記錄失敗、重試和實際耗時；兩組共用鎖定的錄音時，副歌保留率是流程驗收。

以下是給 A、B、C、D 約定格式時的欄位建議。團隊核准後再寫成正式的格式規格及手寫範例。

| 交接資料 | 內容 |
| --- | --- |
| `a_profile.json` | 參考歌手或風格代號、音域、編曲與律動條件、歌詞風格。 |
| `chorus_package` | 副歌素材的相對位置、原始 BPM／調性、起訖、第一個重拍、弱起、核對過的詞曲與樂句。 |
| `plan.json` | 配對 ID、方法、每段起訖小節、目標 BPM／調性、副歌位置、保護及編輯區間、每句音節預算。 |
| `run_manifest.json` | 配對 ID、方法、種子、模型版本、裝置、參數、輸出相對路徑、耗時、記憶體峰值、重試及失敗原因。 |

## 換電腦後從這裡開始

1. 讀四週計畫的決議表，確認角色分配、第一組開發配對及團隊同意的生成順序。歌曲與資料集由組員另外提供。程式、設定與實驗記錄適合進 Git；音檔、模型與機密設定放在本機或團隊約定的共用位置。
2. 若生成機是 RTX 5070＋32 GB 系統 RAM，先用 `nvidia-smi --query-gpu=name,memory.total --format=csv` 查實際 VRAM。12 GB 版可優先驗證正式流程；8 GB 版用 2B Turbo、一次一首先試。Apple Silicon 可走 ACE-Step 的 MLX 路徑，用作原型或備援。兩台尚未用相同專題素材測速。
3. Gate 1（11 月 29 日）驗證固定副歌的 Repaint、生成耗時、記憶體和副歌保留。建議先用 **四小節新段 → 完整副歌 → 四小節新段** 試跑，短版通過後，再以計畫中的 90 秒或 120 秒正式時間軸跑三次，記錄從來源到輸出 WAV 的時間。第一輪只用一組開發素材。
4. Gate 2（12 月 6 日）目標是一個指令產出一首完整歌且評估可跑。Gate 3（12 月 13 日）驗證三種方法並凍結設定。正式規模是 9 組保留至最後的測試配對 × 3 種生成方法 × 3 個種子，共 81 首，另有 9 組直貼片段。若時間不足，依計畫縮減測試配對或種子數，方法之間維持相同預算。
